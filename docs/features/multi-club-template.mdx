## Persona

- **A new club's volunteer or contractor** who wants the same site for their club without writing code.
- **The site operator** who stands up and later updates each club's copy.
- **Lang Lang's own committee**, who must see no change to their site.

## Why it was built

Other clubs asked for the same site. The earlier groundwork kept club values in a few files but a new club still had to fork code, and a blank database came pre-filled with Lang Lang's wording ([#37](https://github.com/sherlabs/lang-lang-cricket-website/issues/37)). The template work removes both: a club is described by a profile file and environment variables, and a blank database holds no club text at all.

## What it does

- **A club profile and a bootstrap script.** `clubs/<slug>/profile.json` describes the club (name, location, colours, PlayHQ organisation, first admin, picture files). `pnpm bootstrap:club --profile clubs/<slug>/profile.json --target <host>/<db>` validates the profile and prints a plan; it is a **dry run unless `--confirm` is given**. A confirmed run migrates a blank database, fills Club details, Site look, Social posts, Club office and Site settings, creates the first admin (password from `INITIAL_ADMIN_PASSWORD`, never from the file), uploads the pictures and writes `clubs/<slug>/env-checklist.md` (variable names and status, never values). It refuses a database that already has a Club details record or users unless `--force`; `--force` fills only empty fields and never overwrites a saved value, deletes data or resets an admin. It refuses when the environment disagrees with the profile (canonical host, cookie prefix, PlayHQ organisation and prefix). It makes no network call. The guide is `docs/template/README.md`.
- **The profile is validated.** Required fields, hex colours, a contrast check of every text and background pair (a failing pair is an error), timezone, locale, currency, an `https://` site address, picture paths that stay inside the club folder, and file type and size. Any key named `password` is rejected.
- **Neutral copy.** `payload/seed/club-template.ts` has `buildClubDefaults(identity)`, which writes the full set of site wording for any club from its name and place. The Lang Lang words moved verbatim to `payload/seed/presets/lang-lang.ts`. `payload/seed/club-defaults.ts` picks the active set from `CLUB_PRESET` (`lang-lang` in development and test, `template` elsewhere). For the template, the home page, page headings and menus are built from the saved Club details, so they name the right club.
- **No club text in the database schema.** The `club` global's field defaults are functions, and the migration `template_neutral_club_defaults` removes the old column defaults. An integration test scans the database for preset words.
- **Lang Lang is protected.** `CLUB_PRESET=lang-lang` must be set on Lang Lang's deployments (production and preview). A build or startup on Lang Lang's host without it fails (`assertClubPreset`), and `verify:cutover` runs the same check.
- **Association wording.** The document section `CCCA Directory` is now stored as `Association directory`; the heading visitors see comes from Club details > Association document section name (Lang Lang's is "CCCA Directory", set by the migration). Extra association honour words are added in Club details > Extra association honour words. Club details also gained a favicon and a home page hero picture; static icons remain the fallback.
- **Search Console and credit.** The verification file is no longer committed; the site serves it at `/google<16 hex>.html` only when `GOOGLE_SITE_VERIFICATION_FILE` names it. `AGENCY_CREDIT=off` hides the footer credit.
- **`pnpm check:template`** (read only) lists every environment variable as set, missing or invalid from one manifest (`config/env-manifest.ts`, which also feeds the generated checklist and the documentation table) and any file under `public/` that is still one of Lang Lang's originals.
- Guard tests: `tests/no-brand-hex.test.ts` also keeps place, association, host and email words out of code; `tests/template-copy.test.ts` keeps the neutral copy and the example profile free of the preset; the preset file may only be imported by seeds, scripts, tests and `club-defaults.ts`.

## How to use it

1. Follow `docs/template/new-club-checklist.md`: copy `clubs/example-fc/`, edit the profile, create the hosting, set the environment variables, run the dry run, then `--confirm`.
2. Sign in, check Club details and Site look, and walk the smoke checklist.
3. Later, merge upstream releases (`docs/template/upstream-updates.md`); a club never edits files outside `clubs/<slug>/`.

## Not included / deferred

- No multi-tenancy: one deployment, database and Blob store per club, by design (`docs/template/deployment-model.md`). The only shared service is the sign-in broker.
- Static artwork (`app/favicon.ico`, `public/apple-touch-icon.png`, `public/assets/...`) stays Lang Lang's in this repository; a new club replaces the files in its own copy (`pnpm check:template` finds the leftovers). The uploaded favicon is added alongside the static one.
- The profile cannot override the home, page-heading and menu wording (they follow the club's name and place); only the fields in Club details are saved. Fees, volunteer jobs and other office settings are edited in the admin.
- The template is not yet published as a GitHub template repository, and releases are not yet tagged `template-vX.Y`; both are the owner's call. The bootstrap needs a PlayHQ organisation, a Vercel project, a domain, an email provider and a broker entry, which the club must supply.
