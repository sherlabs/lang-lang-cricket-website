## Persona

- **A developer** asked to stand up the same site for a different club, who wants to change a small, known set of files.
- **A neighbouring club** that would want its own site without a rewrite.

## Why it was built

The Payload migration spec (section 16) records the intent to keep the code reusable. This is groundwork only: it keeps club-specific content in a few places so a later extraction ([#37](https://github.com/sherlabs/lang-lang-cricket-website/issues/37)) is practical.

## What it does

- Club-specific content is confined to `payload/seed/club-defaults.ts` (names and copy), `payload/seed/theme-defaults.ts` (the seed colours and heading font, the only place brand hex may appear), `config/site.ts`, `public/assets/branding`, `assets/fonts` and the environment. Colours, crest and heading font are edited in the admin under Advanced, Site look ([Site look](./theme-editor.mdx)); `tests/no-brand-hex.test.ts` fails if a hex colour or club name is hard-coded in app, component, admin or image code.
- Environment per club: `CANONICAL_HOST`, `REDIRECT_HOSTS`, `PLAYHQ_ORG_ID`, `PLAYHQ_TEAM_PREFIX`, optional `PLAYHQ_CLUB_URL`, `EXPORT_FILENAME_PREFIX`, `COOKIE_PREFIX`, `CLUB_TIMEZONE`, `CLUB_LOCALE` (see `.env.example`). Outside development and test (Vercel production and preview, or a self-hosted `next start`) `PLAYHQ_ORG_ID`, `PLAYHQ_TEAM_PREFIX`, `CANONICAL_HOST` and `COOKIE_PREFIX` are required: `instrumentation.ts` stops the server when any is missing, so a new club (or its preview deployment) can never show Lang Lang's data or call its PlayHQ. The Lang Lang values are defaults for local development and tests only (`NODE_ENV` development or test). The admin sign-in, dashboard and nav icon show the name from Club details; only the browser tab suffix is the neutral "Website Admin". On production a failed theme read makes the page error (Next keeps serving the last good page) instead of caching the seed colours.
- Sport-specific vocabulary (sponsor tiers, people sections, document categories) sits in `lib/` constants. The document category `CCCA Directory` and the `ccca` honours keyword name Lang Lang's association and are a Postgres enum value, so another club needs a migration to rename them (not done). Cookie names use `COOKIE_PREFIX` (Lang Lang keeps `llcc`).
- The `club` global merges its saved values over `payload/seed/club-defaults.ts`. That file is the **Lang Lang preset** (names, Caldermeade copy, council, sponsor, e-mail, SEO text), not neutral text: any Club details field a new club leaves empty or unsaved still shows Lang Lang's wording. A new club must therefore either fork `club-defaults.ts` before the first `seed:club` or fill in every Club details field (and check the Site look page). Splitting it into neutral defaults plus a Lang Lang preset is a follow-up, not built ([#37](https://github.com/sherlabs/lang-lang-cricket-website/issues/37)).
- The site URL (canonical links, sitemap, robots, structured data) is `https://<CANONICAL_HOST>` whenever that env var is set, which it must be in production, so it can never disagree with the redirects. `seed:club` fails when Club details > Site URL has another host.
- A few static files still hold Lang Lang artwork and have no admin upload: `app/favicon.ico`, `public/apple-touch-icon.png`, `public/og-image.jpg` (default share image), `public/assets/branding/hero.jpg` and `logo.png` (the last link of the crest chain and the admin favicon), `public/googlef3f9083034ceae06.html` (Search Console verification), `public/assets/documents/llcc-conflict-resolution-policy.pdf` and the other documents and gallery photos. `tests/branding-files.test.ts` fails when `CANONICAL_HOST` is another club's host and any of the first group is still byte-identical to Lang Lang's.
- `tests/no-brand-hex.test.ts` also fails when `Lang Lang`, `Caldermeade` or `llcc` appears in code (comments excluded) anywhere except the seeds, scripts, migrations and `config/site.ts`, and its hex scan covers all of `payload/` except those.
- A new club forks those files, runs `payload migrate`, `seed:admin` and `seed:club` (or `seed:demo`), and never runs the ETL. The README "Template notes" section lists the steps.

## How to use it

Treat the README "Template notes" section as the checklist. Do not copy this repository's production data.

## Not included / deferred

- No club-selection at runtime, no multi-tenancy, no light/dark finish switch, no feature flags for clubs without PlayHQ, and no extraction into a separate template repository ([#37](https://github.com/sherlabs/lang-lang-cricket-website/issues/37)).
