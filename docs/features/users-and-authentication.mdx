## Persona

- **The site admin** who invites a new secretary and later removes a former committee member.
- **An editor** who signs in to post an announcement and must not be able to see or change anyone else's account.

## Why it was built

The first site used one shared admin password. The Payload migration replaced it with individual accounts and two roles, so access can be revoked per person and committee members cannot change site-wide settings or other users.

## What it does

- Payload login at `/admin/login`; session cookie is Lax, `secure` in production, valid for 7 days (`tokenExpiration` 604800 s). Payload's default lockout applies after repeated failed attempts, and only an admin can unlock an account.
- Roles: `admin` (looks after the site), `editor` (committee member) and `selector` (picks the teams; see [Selector accounts and Facebook sign-in](./selector-accounts.mdx)). "Staff" means admin or editor only; a selector or a disabled user is never staff. Only an admin can create editors or admins, delete them, or change a role. An editor can read and update their own record, and can create, update and delete selectors only (a forced selector role; an attempt to set another role is a 403). A selector can update only their own name and password, and a password change needs the current one.
- Every password must be at least 10 characters on every path. Disabling a user, a role change, an email change or a password change ends their other sessions.
- The first admin is created by the `seed:admin` script from `INITIAL_ADMIN_EMAIL` and `INITIAL_ADMIN_PASSWORD`. "Create first user" registration is closed in code, so anonymous creation is refused.
- Forgot-password is refused unless outbound mail is configured (see [Bulk email](./bulk-email.mdx)): without an email adapter Payload would log the reset link. When mail is on it works for every account, is rate limited per IP and per address, answers the same for unknown addresses and builds the link from the configured site address only; otherwise an admin sets a new password.
- The Payload REST API is on; GraphQL is disabled. State-changing requests require an allowed `Origin` (CSRF list from the server URL). Public token flows (RSVP edit, story drafts) use unguessable UUID tokens and never use `where`-based writes.
- Access rules by collection are summarised in the migration spec (section 2) and pinned by `tests/int/access.int.test.ts` and `admin-access.int.test.ts`.

## How to use it

1. Admin: **Users**, **Add new**; enter the email, a strong password and choose Editor.
2. To reset a forgotten password, open the user and set a new one, then give it to them in person.
3. To remove someone, delete their user.

## Not included / deferred

- No two-factor sign-in or single sign-on (password reset by email exists only when mail is configured); no per-collection permissions beyond the two roles. Tracking issue: [#38](https://github.com/sherlabs/lang-lang-cricket-website/issues/38).
